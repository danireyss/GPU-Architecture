The big idea: you write code for one element, and the GPU stamps it out a million times.

  • 80 SMs is a V100, the number it ships with enabled. The full die has 84.
  • 8 blocks per SM is Lesson 3.2's 32-register case. The real number depends on the kernel. 65,536 registers ÷ (32 × 256) = 8, and 64 warp slots ÷ 8 warps = 8.
  • 25 GB/s is Lesson 4.4's PCIe figure. Real links and real copies differ.
  • Blocks of 100 keep 8 blocks per SM, so that only one thing changes, which gives 16 waves. By the limits above, blocks of 100 could fit 16 per SM (64 warp slots ÷ 4 warps), giving 8 waves.
Where the numbers come from
  • The model: one pure function, written and tested before drawing. Blocks = n ÷ block size rounded up; threads = blocks × block size; warps per block = block size ÷ 32 rounded up; waves = blocks ÷ (SMs × blocks per SM) rounded up; copy time = bytes ÷ link speed.
  • Lanes idle: lanes = warps × 32, and idle = (lanes − n) ÷ lanes. With blocks of 256 the only idle lanes are the 192 threads the if switches off: 192 ÷ 1,000,192 = 0.02%. With blocks of 100 it is 28 lanes in each of 10,000 blocks: 280,000 ÷ 1,280,000 = 21.9%.
  • Waves are a simplification. A real GPU does not wait for a whole wave to finish. As soon as a block ends, the next waiting block takes its slot, and which SM a block lands on is not something a program can rely on. Seven waves is how many SM-loads of blocks there are, not a timing measurement.
  • Bytes: a, b and c hold 1,000,000 4-byte ints, so 4 MB each. Copy times use 1 MB = 1,000,000 bytes, and leave out latency and setup. They are drawn far slower than real time so they can be seen.
  • V100's SM count comes from reviews and spec tables, not from NVIDIA's whitepaper, which I did not read.
  • Placeholder values: the board uses a[i] = i and b[i] = 2i so that each sum can be checked by eye. New launch sizes are round cases chosen for the figure.
  • The grid squares are drawn to count: one square for each block. The opened block is B2, because it holds element 517, and in the wave plan here it sits in slot 2 of the first SM.
  • Left out: how long the kernel runs, launch overhead, and the real scheduling between warps inside an SM.

Sources for the SM count: AnandTech on Titan V and V100, Wccftech spec table.
