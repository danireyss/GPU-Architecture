Where the numbers come from
  • The model: blocks that fit = the smallest of floor(65,536 / (registers per thread × 256)), floor(64 / 8) and floor(96 KB / shared memory per block). Occupancy = resident warps / 64. An SM only takes whole blocks. Every number in the figure, the chips and the table comes from that one function.
  • Real per-SM numbers: 65,536 32-bit registers per SM is real for every NVIDIA GPU from Kepler to Hopper. The 64-warp cap (2,048 threads) is real for many of them (Volta V100, A100, H100), but it varies by generation: consumer Ampere and Ada GPUs (compute capability 8.6 and 8.9) cap at 48 warps, and Turing at 32. Up to 96 KB of shared memory per SM is real for Volta, but it varies too: A100 allows up to 164 KB, H100 228 KB, and consumer Ampere 100 KB. Source: the CUDA C++ Programming Guide, "Compute Capabilities" table.
  • What the model leaves out: registers are handed out in chunks (per warp, in units of 256 registers on recent GPUs), so a kernel's real register use is rounded up. There is also a cap on resident blocks per SM (16 to 32, depending on the GPU) that can bind for small blocks. And on recent GPUs (Ampere and later) the CUDA runtime reserves 1 KB of shared memory for each block, so a block asking for 16 KB really takes 17 KB. All three can lower the counts shown here. NVIDIA's occupancy calculator (in Nsight Compute) includes them.
  • One drawer = one register for a whole block: a drawer holds 256 registers, and a block has 256 threads, so a block using r registers per thread fills exactly r drawers. 40 registers × 256 threads = 10,240 per block, and 65,536 / 10,240 = 6.4, so 6 blocks fit and 16 drawers (4,096 registers) stay empty because no block fits in them.
  • The die is drawn with four SMs to leave room for the open one. Real GPUs have from a handful to well over a hundred (H100 SXM has 132). The dispatcher stands for the GigaThread engine, the hardware that hands thread blocks to SMs.
  • Occupancy is not speed. More resident warps give the scheduler more to switch between while others wait on memory, but a kernel at 50% occupancy that keeps more data in registers can still be faster.
